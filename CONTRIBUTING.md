# Contributing

## Workflow
1. Find an issue and confirm scope and acceptance criteria.
2. Branch off `main` using `feat/<issue>-short-title`, `fix/<issue>-short-title`, or `docs/<issue>-short-title`.
3. Keep changes small; add tests for behavior changes.
4. Create a PR linking its issue; request a review.
5. Merge only with passing checks. Prefer squash merges.

## Definition of Done
Acceptance criteria met; tests green; docs updated; simulated driver supported for hardware-facing changes; no secrets; reviewed PR.

## Development principles
API-first, modular monolith for core, explicit contracts, hardware-independent simulation, least privilege, predictable companion behavior.

## Licensing
License and external contribution policy are awaiting formal selection; coordinate with maintainers before submitting substantial third-party contributions.
